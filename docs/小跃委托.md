# 可选：内置小跃 → 手机本地 Codex

> **加固分支。** 原桥接的无认证五分钟配对窗口已替换为一次性配对码；桥接默认观察模式，任务执行必须显式开启。完整安装前先阅读 `HARDENING.md` 和主 README。

先完成主教程并验证 CLI 与 MCP。这里只增加普通任务委托，不修改厂商默认模型、不改受保护配置，也不使用厂商原生 GUI Agent / 8765 MCP。

实际流程：小跃的普通端侧执行工具 → 手机 `127.0.0.1:19094` → shell 身份的本地 Codex → 自己的模型 API 与手机 MCP → 小跃查询原编号结果。CLI 独立控屏不需要此桥接。

## 1. 部署并启动桥接

仍在分享包目录的 PowerShell 中，沿用主教程的 `$device`、`$phoneRoot`：

```powershell
adb -s $device shell "mkdir -p $phoneRoot/bridge $phoneRoot/bridge-assets"
adb -s $device shell "chmod 700 $phoneRoot/bridge $phoneRoot/bridge-assets"
adb -s $device push '.\optional\bridge.sh' "$phoneRoot/bridge.sh"
adb -s $device push '.\optional\task-progress.jq' "$phoneRoot/task-progress.jq"
adb -s $device push '.\optional\task-error.jq' "$phoneRoot/task-error.jq"
adb -s $device push '.\optional\client.py' "$phoneRoot/bridge-assets/client.py"
adb -s $device push '.\templates\bridge.config.toml' "$phoneRoot/config/bridge.config.toml"
adb -s $device push '.\templates\phone-policy.txt' "$phoneRoot/config/phone-policy.txt"
adb -s $device shell "chmod 700 $phoneRoot/bridge.sh"
adb -s $device shell "chmod 600 $phoneRoot/config/bridge.config.toml $phoneRoot/config/phone-policy.txt"
adb -s $device shell "nohup /system/bin/sh $phoneRoot/bridge.sh --serve --profile assist --enable-tasks </dev/null >$phoneRoot/bridge/listener.log 2>&1 &"
```

只在尚未运行此服务时启动；不要对已有配对或正在执行的任务重复初始化。默认只观察；`--enable-tasks` 才是自动化执行开关。网络只监听手机 loopback，不能把监听地址改成 `0.0.0.0` 后公开使用。

让小跃用**自己的普通端侧 Python 执行工具**先做只读健康检查。这里的 Python 属于小跃可访问的执行环境，不是 ADB shell；不要求 ADB 能进入厂商 rootfs。此时不要从 `/assets/client.py` 下载文件，资产路由也要求下面的配对码。

```python
import json
import urllib.request

http = urllib.request.build_opener(urllib.request.ProxyHandler({}))
base = 'http://127.0.0.1:19094'
with http.open(base + '/health', timeout=3) as response:
    health = json.load(response)
assert health.get('ok') is True
print(json.dumps(health, ensure_ascii=False))
```

如果当前版本的小跃没有这样的执行工具，或访问 loopback 被拒绝，应先停在这一步排查；不能靠更改一句聊天提示词保证接入。

## 2. 在朋友自己的手机重新配对

准备好小跃端代码后，在电脑开启一次五分钟配对窗口。终端会打印一次性码；它只在本次配对有效，成功后会立即删除：

```powershell
adb -s $device shell "/system/bin/sh $phoneRoot/bridge.sh --pair-window"
```

把 `optional/client.py` 通过你自己的文件渠道放入小跃可访问的本地目录。若只能从桥接下载，先设置 ADB 终端输出的 `STEPNEO_PAIRING_CODE`，并用带自定义头的请求获取；不要从不校验来源的本机端口直接执行脚本：

```python
import json
import os
from pathlib import Path
import urllib.request

code = os.environ['STEPNEO_PAIRING_CODE']
assert len(code) == 64 and all(c in '0123456789abcdef' for c in code)
http = urllib.request.build_opener(urllib.request.ProxyHandler({}))
target = Path.home() / '.local/share/stepneo-phone-codex/client.py'
target.parent.mkdir(parents=True, exist_ok=True, mode=0o700)
request = urllib.request.Request('http://127.0.0.1:19094/assets/client.py',
                                 headers={'X-Pairing-Code': code})
with http.open(request, timeout=3) as response:
    data = response.read(65536)
assert data.startswith(b'#!/usr/bin/env python3')
target.write_bytes(data)
target.chmod(0o600)
print('客户端已保存；现在执行 client.py pair，仍使用同一个配对码')
```

随后在同一个五分钟窗口内运行：

```sh
STEPNEO_PAIRING_CODE=<ADB 终端显示的一次性码> python3 ~/.local/share/stepneo-phone-codex/client.py pair
```

客户端只在配对成功后保存随机令牌到 `~/.local/state/stepneo-phone-codex/client.json`。如果配对失败，保留现有令牌，使用同一个码重试；服务端会一次性消费配对码。不要把配对码、令牌或 `client.json` 交给模型、聊天或分享包。

这段首次配对示例未在朋友的新机上验证。若明确返回 `pairing_expired` 或 `pairing_closed`，且确认服务端尚未写入令牌，可保留同一个客户端令牌重新开窗并配对；结果不明时先检查，禁止直接删除双方状态反复尝试。

不要把 `client.json` 的内容交给模型、复制到聊天或分享给别人。模型 Key 在 Codex 自己的登录文件，桥接令牌在小跃自己的状态文件，两者用途不同。

## 3. 自检、提交一次、查询原编号

下面命令仍由小跃的普通执行工具在自身环境运行，不是在电脑 PowerShell 中执行。先把任务写入文件，避免把完整用户任务放进进程命令行：

```sh
python3 ~/.local/share/stepneo-phone-codex/client.py doctor
printf '%s\n' '只读取手机状态和当前 UI，简短概述，不点击、不输入。' > ~/.local/state/stepneo-phone-codex/demo.txt
python3 ~/.local/share/stepneo-phone-codex/client.py run --request-id demo-phone-001 --prompt-file ~/.local/state/stepneo-phone-codex/demo.txt --wait 4
python3 ~/.local/share/stepneo-phone-codex/client.py status demo-phone-001 --wait 4
```

`assist` 档会拒绝坐标点击、`ENTER`/`DPAD_CENTER`、默认策略中的支付/转账/删除/授权/发送类文字，以及设置和支付宝包；`observe` 档只开放状态、能力探测、查找、等待、UI 和截图。需要更宽的执行范围时，必须由设备所有者显式改档并重新启动桥接。

`doctor` 只检查版本，不调用 Codex 模型 API；小跃自身理解和执行请求可能仍有它的正常模型用量。`run` 会调用朋友配置的模型服务。

实际任务使用新的唯一编号；同一任务 POST 一次后，反复短 GET 原编号即可。当前客户端单次等待最多六秒，HTTP 默认三秒；服务总期限为 600 秒、单任务并发。这些期限不是同一回事。GET 会返回状态、工具完成/失败数、最后工具、期限来源及剩余时间。

请求超时或结果不明时，**保留编号查询，不要换编号自动重投**。最终回答为空也不能判断“完全没有执行”；应结合进度和屏幕实际结果。截图用于模型感知，默认不进图库。

## 4. 保存普通说明和委托偏好

把同包 `optional/AMOO_README.txt` 作为普通文本，让小跃用正常文件工具保存到它自己的：

```text
~/.local/share/stepneo-phone-codex/README.txt
```

再通过正常记忆界面保存一条偏好：

> 当我要求交给手机本地 Codex 时，先读取 `~/.local/share/stepneo-phone-codex/README.txt`，使用已经配对的客户端提交一次任务，再查询原编号并报告实际结果。不要展示、读取到聊天或修改任何凭据。

本次普通说明与持久配对已在新聊天中验证可以复用。这是偏好委托，不保证所有聊天都强制进入 Codex。这里没有安装原生 OpenClaw Skill，也没有替换默认聊天后端。

## 恢复与自启状态

重启或系统结束服务后，先核对 19094 监听、旧 worker 和 `bridge/active`；确认没有在运行的任务后再恢复监听。保留配对和任务记录，不要为了恢复就删除 active 或重新配对。

本方案尚未完成开机自启、服务守护、Shizuku 配对及重启验收，也未验证长时间断开电脑后的独立运行。手机普通端侧服务存活时的委托已实测，不能据此承诺永久在线。

分享版没有提供旧实验性的原生技能安装器；对应两个实验资产路由已从分享副本删除。固定任务执行、配对和查询逻辑来自已验证实现。
